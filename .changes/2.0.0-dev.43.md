## 2.0.0-dev.43

Released November 03, 2026

### Features

- Add support for BigQuery query reservation configuration at model and connection levels ([#15486](https://github.com/dbt-labs/dbt-core/issues/15486))
- Report whether each node ran remotely, locally, or on Lake Compute in anonymous usage telemetry.
- Show a determinate progress bar for the parse phase in interactive terminals, matching the render/analyze/run experience, and name the stage in progress (building model nodes, resolving data tests, typechecking macros) during the stretches where no assets are being parsed, plus a progress indicator while the semantic manifest is validated, so the console no longer looks idle
- Rename the --run-cache-mode CLI flag to --state-mode to match the dbt State terminology it configures. --run-cache-mode is kept as a deprecated alias and will keep working, with a warning, until it is removed in a future release.
- Add state configuration to ignore external modifications on model target tables/views (only implemented for views to begin with)
- Support the `allow_jinja_file_extensions` project flag, so resource files may carry a trailing Jinja suffix (`model.sql.j2`, `doc.md.j2`) ([#16296](https://github.com/dbt-labs/dbt-core/issues/16296))
- Add telemetry for state selector operations to track performance and usage of modified/new/unmodified node selection
- Support authenticated private S3 downloads for dbt update manifests and binaries.
- Add DBT_CLOUD_LOGIN_HOST (and optional DBT_CLOUD_LOGIN_ACCOUNT_ID) so dbt login can authenticate through an account host's /oauth/authorize instead of the registration page, for SSO accounts the registration page cannot route.
- [docs v2] Add resource filter to lineage view to select what resource types are displayed in the DAG
- Add a feature flag registry with `--feature NAME[=VALUE]` and `DBT_ENGINE_FEATURES` for setting unstable features; behavior flags and the git deps fast path now resolve through it with unchanged defaults
- Add the ThreadPoolWait telemetry span for runtime pool queue waits, superseding ConnectionLimitWait
- Report individual microbatch executions as MicrobatchEvaluated spans in telemetry, file logs, and Core-compatible JSON logs, and list them under their model in interactive output
- Thread pool wait spans now record the unique_id and batch_id of the node or microbatch they belong to
- Read and publish AWS Databricks Unity Catalog tables through Lake Compute using profile PAT or OAuth M2M credentials. Use canonical lower-case relation names and full-refresh existing models when adopting propagation with mixed-case database or schema names.

### Under the Hood

- Refresh README with a dbt v2.0 DAG screenshot stored in `assets/` and point the CI badge at the current `dbt-labs/dbt` workflow.
- Allow metadata freshness checks to use an explicit artifact directory.
- Allow base Jinja context builders to reuse a caller-provided ResultStore.
- Log a warning naming the relation when no schema is returned for a dangling source during static analysis hydration, instead of skipping it silently.
- Reuse the parsed Jinja AST when extracting unrendered config() arguments.
- Extend package metadata with cross-project environment routing fields.
- dbt-parser: avoid a second, redundant Jinja parse when statically recovering source() calls hidden in a conditional branch during model, function, and singular data test rendering
- Add a per-resource-type applicability table for adapter-specific config keys, replacing the shared WarehouseSpecificNodeConfig field list with per-(resource type, key) status. A key set on a resource type that does not support it now emits a DeprecatedConfigKey warning. On schema.yml and inline config() the key is still applied, so behavior is unchanged; in dbt_project.yml, where the key has no field to deserialize into and already warned, it is dropped.
- Time Machine replay pins the Jinja wall clock to the recording start, so wall-clock-derived SQL (e.g. a `utcnow()`-based var) matches the recorded text
- Add force closing of span subtrees to dbt-tracing, ending a span's structured telemetry even while other handles to it or its descendants are alive.
- docs-v2: document the __overview__ landing-page customization block in the README
- Ignore `flags:` in installed packages' `dbt_project.yml`: project flags, including behavior change and adapter behavior flags, only apply from the root project

- Update ADBC drivers to Snowflake 0.21.21, BigQuery 0.21.23, BigQuery Foundry 0.1.11, Databricks 0.21.15, Redshift 0.18.11, Spark 0.1.4, DuckDB Extended 0.0.32, Lake Compute 0.1.13, and MSSQL 1.7.1 (dbt build suffixes).

### Security

- Pass git package URLs, revisions, and subdirectories to git after `--` in `dbt deps`
- Harden Databricks logged-SQL credential redaction: match `credential` and `encryption` clauses case-insensitively, redact every clause rather than only the first, and correctly handle option values containing commas, newlines, quotes or escaped quotes and keys containing dots. ([#16053](https://github.com/dbt-labs/dbt-core/issues/16053))
- Checks and `dbt show --info`/`--inline` now run in a DuckDB database that can read only the project metadata: no other files, no network access, and no extension installs
- Upgrade gix to 0.84.0 to address security advisories in the gix dependency family.
- Update BigQuery and Spark ADBC driver builds to Go 1.26.10.
- Update rustls-webpki to 0.103.16 and webpki-root-certs to 1.0.10 to reject distrusted certificate chains.
